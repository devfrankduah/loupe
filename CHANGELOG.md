# Changelog

## 0.2.0 (unreleased)

The first release on PyPI, as `loupe-scan`. On release day "(unreleased)" becomes the date; [docs/releasing.md](docs/releasing.md) has the steps.

Two of these break existing scripts: `--json PATH` is now `--json-output PATH`, and exit code 1 now means a finding `--fail-on` counts, where it used to mean a failed fetch.

- The package is `loupe-scan`, imported as `loupe_scan`, and the command is still `loupe`. It installs from this repository until it's on PyPI, and a test fails if any file tells people to install `loupe` or `loupe-scan` from PyPI before then.
- `--json` prints the results as a JSON array instead of the text report, and `--json-output PATH` writes the same array to a file, in place of `--json PATH`. Each page carries `schema_version` 1 and an `error` object with a `kind`, which replaces `html_error`. `docs/json.md` describes the format and `docs/schema/results-v1.json` is its JSON Schema, which the tests check the output against in both scan modes. `loupe report` still reads the older files.
- Exit codes: 0 when every page was scanned and none had a finding `--fail-on` counts, 1 when one did, and 2 when a page couldn't be scanned in full or loupe couldn't run. 1 used to mean a failed fetch. `--fail-on` takes `instructions`, the default, `hidden` or `never`, and a nonzero exit says why on stderr.
- A typed Python API: `scan()`, `Scanner` for several pages, `ScanResult` with `to_json()`, and `ScanError`, raised for a page that couldn't be scanned so it can't pass for a clean one. The package ships `py.typed`. `docs/python.md` has an example of checking a page before handing it to a model, and the tests run it.
- `loupe mcp` renders a redirected page at the address it ended up at, as its markup scan already read it, so the page's relative stylesheets, scripts and frames load from where they're meant to. A page at `/guide` that redirected to `/guide/` and hid an instruction with a relative stylesheet was rendered at `/guide`, where the stylesheet didn't load, so in auto mode the instruction looked visible and strip mode handed it to the agent. The header still names the URL the agent asked for.
- A page that redirects to a URL that can't be read, such as one with an unclosed bracket, fails as `it redirects to an invalid URL`, and a linked stylesheet whose `href` can't be read counts as one not read. Both used to stop the whole run with a traceback and exit 1, the code for a finding, before the JSON was written. A robots.txt that redirects to one counts as unavailable, as RFC 9309 has one that redirects too often.
- A URL with a space or a control character in it, such as two URLs run together in one argument or line, is refused before any request with a message saying it isn't a valid URL and to write a space in a path as `%20`. One with a space in its host used to fail as a robots.txt that couldn't be read. The command, the Python API and `loupe mcp`'s tools all check URLs the same way.
- `--urls-file` reads URLs from a file or standard input. Each URL is scanned once, one page at a time, reading each site's robots.txt once and waiting out its Crawl-delay, and several pages end with a summary table.
- A GitHub Action, `action.yml`, installs loupe at the ref a workflow names, scans the `urls` input, uploads the JSON as an artifact and fails the step by `fail-on`. `docs/ci.md` has a workflow for scanning a site after each deploy, and CI runs the action against the test pages.
- The action writes a job summary with each page's result and counts and the exit code, through a new `--markdown-summary PATH` option that adds the summary table to the end of a file as Markdown. Every action it and CI use is pinned to a commit SHA, with the release in a comment.
- `scan_html(html, url)` and `loupe --html-file PATH URL` scan HTML the caller already has and fetch nothing, so a site that serves agents a different page from the one loupe would fetch can't slip past. The markdown is made from the same HTML. With `render`, local Chromium is given the HTML as the page at that URL and kept on it when a script tries to load another document, and `docs/python.md` says how that can differ from a live load. The JSON marks these pages with `supplied_html`.
- `loupe mcp` serves loupe to agents over MCP, from a new `mcp` extra built on the official MCP Python SDK. Its `fetch_page` tool fetches a page once, scans that HTML and returns its markdown under a header with the verdict and counts. By default it takes the hidden text out (`--mode strip`); `--mode flag` leaves it in and says so, and `--mode block` withholds a page that hides instructions. `scan_page` returns the report. Neither tool quotes hidden text unless the server starts with `--quote-hidden-text`. robots.txt, Crawl-delay, the time and size limits, one page at a time and public addresses only are set when the server starts, and no tool call can change them. `docs/mcp.md` sets it up for Claude Code and Claude Desktop.
- robots.txt is read again once it's a day old, as RFC 9309 asks, for a server that runs for days.
- The markup scan applies stylesheets in part, without a browser. It reads the page's `<style>` blocks and up to five stylesheets linked from the page's own host, fetched under the same robots.txt, Crawl-delay, address and time rules as the page and only when served as `text/css` and under 2 MB, and applies their rules with selector matching and the cascade for `display:none`, `visibility:hidden`, `opacity:0`, `font-size:0`, offsets of 1000px or more off the page, and `clip` or `clip-path` that leaves nothing showing. Rules in conditions it can't settle at the rendered scan's 1280 by 800 viewport, such as `@supports`, `@layer` or most media queries, never count as hiding and can only clear an element. What it finds is a new `stylesheet` kind, and the text report, the JSON (`stylesheet_check`), `ScanResult.stylesheet_check` and `fetch_page`'s header all call the check partial. On the blender test page the two items a stylesheet class hides are now found without `--render`, so `fetch_page` strips them in a markup-only scan, and on the animated page the invisible layout copy of the headline is flagged too. Inline styles also count `clip` and `clip-path` that leave nothing showing, and `!important` now beats a later declaration in the same style attribute.
- New direct dependency: soupsieve (MIT licence), which Beautiful Soup already installed.
- A release workflow, `.github/workflows/release.yml`, publishes to PyPI through trusted publishing when a GitHub release is published, and at no other time. It checks the release's tag against the package version and the distributions with `twine check --strict` first. [docs/releasing.md](docs/releasing.md) has the one-time setup on PyPI and GitHub, and its release steps name every install instruction to switch to PyPI afterwards. `CITATION.cff`'s abstract no longer says loupe runs on Bright Data's Browser API.
- Every link and image in the README is absolute, so the project's page on PyPI shows the images and its links work, and a test fails on a relative one.
- The package metadata gives its licence as the SPDX expression `MIT`, with the licence file named in `license-files`, which building now needs setuptools 77 or newer for.
- A public-only fetch, as `loupe mcp` makes, connects to an address that passed its check and to nothing else, keeping the site's name in the Host header, in TLS's server name and in the certificate check. A name that answers the check with a public address and the connection with a private one (DNS rebinding) can no longer reach this machine or its network. Such a fetch ignores proxy and CA bundle settings in the environment.
- A rendered scan reports text in the HTML as served that the page's scripts took out, as `rendered-hidden` with the reason `removed by a script`, when that text reaches the markdown. Text a script only changes, such as a date or a clock, doesn't count.
- `fetch_page`'s strip mode tidies the markdown it emptied: a bullet, heading or quote left with nothing in it goes, and so do empty bold or italic markers, an emptied link title and a link left with no text.
- `loupe mcp`'s rendered scans keep Chromium to public addresses too. Every request the browser makes for the page goes through a proxy on this machine that resolves the host, refuses anything private, loopback or otherwise not public, and connects only to the address that passed, so redirects, frames, scripts' requests and WebSockets can't reach this machine or its network. `--allow-private-addresses` turns it off with the rest of the check.
- Text coloured like its background is found. A rendered scan compares each visible piece of text with the solid colour painted under it and calls it hidden below a WCAG contrast ratio of 1.5:1, well under the 3:1 WCAG asks of large text, so faint but readable text stays visible. Text on an image, a picture or a gradient of several colours isn't judged, and the rendering notes count it. A gradient whose stops are all one colour counts as that colour. The markup scan makes the same check where the page's styles declare both colours. The blender test page's coloured line and the harness's background-colour page are now found in both modes.
- A rendered scan checks text in shadow roots and frames. Open shadow roots, and closed ones found through the DevTools protocol, are checked like the rest of the page, with their own styles and slots. Frames, same-origin or cross-origin, up to 20 within 30 seconds, are checked after the page, each in an isolated world of its own: a frame whose `<iframe>` a reader can't see has all of its text reported, and any other is scrolled through and checked like a page. A finding says where it is, such as `display:none (in a frame)`, the JSON's `rendering` gains `frames_checked`, and the notes count the frames that couldn't be checked. Text in a frame never reaches markdown made from the page's HTML; text in a shadow root declared in that HTML does.
- Text written inside an `<iframe>`, `<video>`, `<audio>`, `<canvas>`, `<noframes>` or `<noembed>` tag is found in both scan modes, as a new `fallback-content` kind. A browser shows it only when it can't show the element itself, and markdownify keeps it, so an agent read it where a person never could. Text in `<noscript>` or fallback content inside another hidden element is now reported on its own, so a rendered scan, which replaces the outer element's markup finding with its own, no longer loses it.
- The markup scan checks a shadow root declared in the HTML, with `<template shadowrootmode>`, with the `<style>` blocks and same-host stylesheets inside it, and keeps the page's own rules out of it, as a browser does. Its selectors are matched in a copy of the shadow root on its own, so they can't see past it. It's partial: `:host`, `::slotted` and slots aren't modelled, and the colours a host passes down aren't followed. A finding in one says `(in a shadow root)`, and `stylesheet_check` gains `shadow_roots`. The harness's shadow-root page is now found without rendering. Text inside a hidden host now includes its shadow root's.
- `loupe mcp`'s tools scan in a new auto mode by default. They run the markup scan, and render the page in Chromium as well when it holds something only a browser can judge: frames, a declared shadow root, scripts, stylesheets the markup scan couldn't read, rules it couldn't settle, elements placed where they could cover text, styles or colours it can't judge, or content that opens on a click. `docs/mcp.md` lists exactly what counts; `overflow` that clips counts on its own, since a `line-height` or an indent can clip a box's text away with no size set. `--scan markup` and `--scan render` fix the scan for every call, and a call's `render=true` still asks for rendering in auto mode. The header's new `mode:` line, and `scan_page`'s `scan_decision`, say which scan ran and why. Without Chromium, or when the page won't load in it, auto returns the markup scan's result and the header says covered text, shadow DOM, frames and what scripts do weren't checked, with the install command. The old `note:` line about markup-only scans is gone.
- The markup scan reads colours set with `var()` when the custom property is set once on the page, on `:root` or `html`, and nowhere else, and takes a `var()`'s fallback when its property is set nowhere. Any other `var()` leaves the colour unjudged, as before.
- The markup scan takes a `background` shorthand's colour as unjudged when it's in a notation the check can't read, such as `light-dark()` or `color-mix()`, or a name outside CSS level 1, where it used to skip it and take the background as transparent, which could call readable text on a dark card hidden. example.com sets its background with `light-dark()`, so `fetch_page`'s auto mode now renders it.
- The harness's guarded condition scans in auto mode by default. `--guarded-scan {auto,markup,render}` replaces `--markup-only`, `--condition` runs one condition alone, and the results record the scan the guarded tool's header gave for each page. Each canary page's ground truth says whether auto renders it and whether it hijacks through auto.
- An SVG's `<title>`, `<desc>` and `<metadata>` are found in both scan modes, as a new `svg-label` kind, and so is text inside a `<template>` that isn't a declared shadow root, as `template`. A browser draws neither, and markdownify keeps both. A rendered scan drops a template's finding when a script copied the template onto the page, where the browser judges the copy.
- A rendered scan finds text covered by another element. Hit testing at five points in each of the text's first four boxes finds it under an element that paints a solid colour at least 95% opaque, and an `<iframe>` under one hides its frame's text. Fixed and sticky elements, dialogs and open popovers don't count, since the page scrolls under them, so headers, cookie banners and modals don't flood the results. Text under an image, a picture or a gradient of several colours isn't judged, and the notes count it. The animated test page's results don't change.
- When a markup scan of a page that runs scripts finds hidden text, `fetch_page`'s verdict line and `scan_page`'s `verdict` say the scripts may show some of it and that `--scan render`, or the default `--scan auto`, runs them, or, when auto couldn't use a browser, that it couldn't run them. A stylesheet can hide an article until a script shows it, as one of OWASP's pages does. The findings are unchanged.
- The harness's dry run estimates a local model's time from what the runs in `docs/hijack-rates.md` measured: 3,400 prompt and 25 output tokens a second, and the output tokens a trial took in each condition, about 230 raw and 126 guarded, where it used to guess the speeds and put every request at its cap. It gives about 55 minutes for a default run at a 400-token cap, which took 52, where it used to give 3 hours 36 minutes. The cost estimate still puts every request at its cap.
- The harness's base URL, `https://devfrankduah.github.io/loupe/harness/`, has an index page listing the canary pages, how each hides its instruction and a link to each ground truth, where it used to answer 404. It holds no instruction, no code and no hidden text, and the build script writes it with the pages.
- The hijack harness has three more canary pages: `shadow-root`, which hides its instruction with a shadow root's own style, `iframe`, which puts it in a frame with no size, and `covered`, which lays a box the page's colour over it. Each has its own code, a ground truth the tests check and no axe violations, and a default run is now 11 pages, 440 trials a model.
- `docs/mcp.md` says that flag mode passes the page's markdown through unchanged, hidden text and all, so the rule against quoting hidden text covers loupe's own header and report only.
- `python -m loupe_scan` runs the command, and the version lives in one place, `src/loupe_scan/_version.py`.
- New test dependency: jsonschema, with types-jsonschema for the type check.
- New optional dependency: the MCP Python SDK (`mcp`, MIT licence), 2.3 or newer, for `loupe mcp`.
- `docs/social-preview.png` carries the repository's new description: loupe runs locally, with Bright Data as an option for sites that block bots.
- `docs/demo.gif` is recorded again from 25 November's output on the local backend, in a 150 by 28 window so the verdict and the exit line both fit. The published report page is rebuilt from the 25 November local runs, and a test checks that the README's `loupe report` command builds it byte for byte. Its screenshots are `docs/screenshot-desktop-2026-11-25.png` and `docs/screenshot-phone-2026-11-25.png`, in place of the 19 November ones. `docs/social-preview.png` is unchanged: the github.com line it shows is still found hidden in both modes, though the report page now features a line from Wikipedia.

## 0.1.0

The version in `pyproject.toml` has been 0.1.0 since the first commit, and nothing is tagged yet. Each heading below is the day the work landed on `main`.

### 20 November 2026

- loupe works with no account. A local backend fetches pages from your machine, renders them in local Chromium with the same checks as the Browser API, and makes the markdown with markdownify (MIT), labelled an approximation of what agent tools produce. It picks itself when no Bright Data value is set, `--backend` overrides that either way, and the output and JSON name the backend each page used.
- The local fetch names loupe and its repository in its user agent, obeys robots.txt (with `--ignore-robots` for pages you own) and any Crawl-delay, and has time, redirect and 10 MB limits. A 403, a 429 or a Cloudflare challenge is reported as a block, with a link to the Bright Data section of the README.
- Each page's output starts with a plain-English verdict: how many pieces of hidden text read like instructions to an AI and how many of those reach the markdown, then the total amount of hidden text. The JSON keeps it as `verdict`.
- The tests run on the local backend only, against fixtures served from 127.0.0.1 in both scan modes, and fail any connection beyond the machine. Both test pages' ground truths pass end to end on the local backend, and live local runs of both pages match the 19 November Bright Data runs finding for finding.
- The README's quickstart needs no account, and Bright Data moves to a section for sites that block bots and for scanning at scale. The demo GIF shows the quickstart scan on the local backend.
- New dependencies: markdownify, Protego, and urllib3 2.2 or newer, which requests already installs.
- The Playwright install hint now installs from the repository folder, since `loupe` on PyPI is an unrelated package.

### 19 November 2026

- The README is rewritten for anyone building an agent that reads the web: what loupe catches and who it's for first, then a quickstart that needs no account, a plain guide to reading the output, and the deeper sections after.
- `docs/demo.gif` is recorded again, on the blender test page through the Browser API, with quotes cut to 80 characters so all 20 lines fit the window. New screenshots of the rebuilt report page are `docs/screenshot-desktop-2026-11-19.png` and `docs/screenshot-phone-2026-11-19.png`. `docs/social-preview.png` was generated again from the rebuilt page and came out unchanged.
- The results and every mention of a personal site that was one of the five pages scanned are gone from `main`, along with the demo GIF and screenshots that showed it; the git history keeps them. The README, `docs/how-it-works.md` and the report page now use the 19 November runs of four public pages and both test pages, and the animated test page takes over as the example of false alarms. The report page's byline no longer names a person, and its caveats no longer cite "assistant" as a listed phrase.
- A second test page at `docs/animated-page/`: a landing page for a made-up travel pack with scroll fades, a headline that rotates over an invisible layout copy, a live clock, a skip link and a collapsed menu, and nothing planted. Its ground truth says every hidden-text flag from the markup scan is a false alarm and the rendered scan clears all of them, and the tests check both modes against it.

Its ground truth says what loupe should report for each, including the background-coloured line it misses, and the tests check both scan modes against it.
- The README now runs from what loupe catches through a quickstart, one results table and the limits. The detail moved to `docs/how-it-works.md`.
- CI runs the tests and `mypy --strict` on Python 3.10 and 3.13 for every push to `main` and every pull request, with Chromium installed for the rendered tests.
- The dark mode control is a switch named "Dark mode" in both modes, so a screen reader hears "Dark mode, on" or "Dark mode, off". In dark mode the moon fills in and the border takes the accent color. Light mode looks the same as before.
- A demo GIF at the top of the README, recorded by `scripts/record-demo.sh` with asciinema and agg.

### 7 November 2026

- Ran the five pages again, markup only and with `--render` through the Bright Data Browser API, in `results/2026-11-07-2.json` and `results/2026-11-07-2-rendered.json`, after an earlier pair from the same day that came before the watch described below. All of the 2 and 7 November results were removed from `main` on 19 November; the git history keeps them.
- Any part of the Browser API endpoint that turns up in an error is replaced with `[endpoint]`.
- Bytes and refused requests are counted through Playwright's own events, and each rendered page records the viewport it reported.
- "assistant" no longer counts as instruction-like. On real pages it only ever named products and projects, including five false matches in one project's name on 2 November.

### 6 November 2026

- Added `--render`, which loads each page in Chromium, local or through Bright Data's Browser API, scrolls it, centres elements still hidden after the scroll, and reports text a browser never shows.
- Text faded below 0.05 opacity counts as hidden.
- Each inline-style finding from the markup scan is traced through the rendered scan.
- `loupe report` sets a markup-only run and a rendered run side by side.
- Per-request meta values (nonces, CSRF tokens, request IDs) are removed before they're reported.
- Control characters in page text are escaped in the terminal summary.
- A remote browser gets longer timeouts, skips images, media and fonts, and counts the bytes it transfers.
